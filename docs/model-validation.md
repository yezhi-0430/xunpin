## 配置与边界

用户选择 DeepSeek-V4.1-Flash-1017。按 [DeepSeek 官方文档](https://api-docs.deepseek.com/) 与 [2026-10-17 更新说明](https://api-docs.deepseek.com/zh-cn/news/news261017/)，当次调用使用 API 别名 `deepseek-flash`，基础地址 `https://api.deepseek.com`。别名可能随供应商更新，实际响应只作为本次记录。

密钥只在被 Git 忽略的本地 `.env`；`.env.example` 不含密钥。配置后重启 `uv run python run.py`。回放可发送构造文本；正式数据还需来源许可、商品白名单、时效及 `AI_ALLOWED` 校验。每日默认最多 20 次 HTTP 请求，失败请求同样计数；一次事件最多两次请求、一次只读工具，不自动连续重试。

## 人工查看与待验证项

页面已经展示评价主题、使用场景和促销机制，每项附本次实际发送片段的逐字引文；新增评价总数与引用条数由程序计算。模型的建议包含动作、负责人、核实条件、观察指标及评估计划。建议不会覆盖规则任务或人工反馈。

人工查看也发现需要继续审核的推测，例如“竞品可能……以回应该评价”。快照并不能证明商家动机、评价发生顺序或因果；这类文字仅放在“谨慎推测 · 待核实”，不能作为事实采纳。引用匹配只能证明原文存在，不能证明所有推论成立。

这是一组开发中的连通性与输出契约冒烟检查，没有独立人工标注、盲评、多品类或真实市场样本，不报告语义准确率。当前 62 案例规则评估另行记录，不能与本表混算。后续应固定独立文本集，覆盖无实质变化、少量样本、提示注入和拒答，由人工分别评估提取正确性、引用支持度、建议可执行性与过度推断。
