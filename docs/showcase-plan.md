## 2. 四个实施阶段

### 阶段 A：通过数据接入验证

执行 [数据接入核验](data-access.md)。取得适用来源、实际字段、使用条件和脱敏请求记录。没有通过时，可以准备本地逻辑验证，但不能把真实接入阶段标记为完成。

### 阶段 B：先让采集服务可靠

实现来源适配、定时调度、执行锁、缓存、快照和异常状态机。以真实小样本运行至少三个周期，同时注入限流、授权失效、结构变化和重复调度验证风险机制。

### 阶段 C：实现有证据的分析与任务

按可用字段实现五类内容变化检测，接通真实模型；检查数字和证据引用；生成信息优化、促销调整、美工素材任务，记录人工处理。

### 阶段 D：整理 GitHub 与录屏

提供安装运行说明、数据来源说明、权限边界、字段覆盖、架构、测试命令、截图与演示步骤。视频尚未录制，仓库尚未上传。公开前清理密钥、个人信息及未获准公开的响应，并核对许可范围。

## 3. 录屏脚本（目标约 4—5 分钟）

1. **业务与来源，约 45 秒**：说明品类、本店与竞品、数据来源和实际覆盖字段。展示脱敏的接入状态；未获权限时明确展示未启用状态。
2. **定时获取，约 45 秒**：展示真实执行时间、下一次调度、快照和来源时间。重复点击不会重复请求。不能用进度条动画代替执行证据。
3. **AI 分析，约 75 秒**：打开一个事件，展示标题或描述的前后文本、可比价格或促销条件、评价样本，再看模型解释与引用证据。
4. **运营任务，约 45 秒**：展示可执行的优化、促销或素材需求，选择采纳或驳回并记录理由。目标指标是待观察项，不冒充实测增长。
5. **风险与评估，约 60 秒**：用明确标为故障注入的 429 或权限失效响应展示退避、暂停及恢复条件；展示测试指标和局限。

真实来源与逻辑回放分开标注：真实接口不保证录屏时恰好发生变化，因此可使用脱敏且获准展示的历史真实快照；没有这类记录时使用明确标注的构造样例，只展示逻辑效果。

当前可按 [实际可录提纲](interview-notes.md) 展示构造商品、真实模型输出与人工复盘；查看已保存的 AI 解读无需再次调用 API。商品来源仍未接通。离线评估可展示 [62 个构造案例的报告](../artifacts/evaluation.md)，不能把该结果说成模型准确率。

## 4. GitHub 发布前的逐项检查

- 题目四项要求均有对应的设计与证据，未通过的部分单独列出。
- 没有凭证、商家个人信息、未获准再分发的数据；示例配置与实际凭证分开。
- 新环境可以安装并启动，文档操作和实际界面一致。
- 商品选择、快照、事件、建议使用同一条可追溯的数据链。
- 请求去重、限频、异常识别和自动暂停有可重复检查。
- AI 不可用时呈现真实状态；没有编造历史、来源、置信度或收益。
- 本店与竞品字段覆盖分别说明，不把本店权限描述成全网权限。
- 视频中的“已实现”“已验证”与仓库状态一致。

题目本身不要求提交代码。如果接入权限无法在面试前取得，以完整方案、接入核验过程和明确标注的流程验证材料答题；如实解释尚未完成的接入条件。
