# 按面试题复核：优化优先级

复核时间：2026-10-21。依据题目四项目标，对照当前方案、代码和验证记录。结构化 AI 与人工复盘已按用户确认完成本轮增量；其余方向仍是计划，未实施的新能力不得作为已完成内容展示。

## 题目要求与当前缺口

| 要求 | 当前可展示 | 优化方向与验收 |
| --- | --- | --- |
| 合规定时获取公开商品信息 | 来源配置、白名单、调度、预算和模拟请求测试；真实来源尚未接通 | 等待出题方回复，按真实来源补字段覆盖、时间语义与至少三个调度周期记录；记录部分覆盖，不用一个商品详情接口代表五类信息全覆盖 |
| AI识别标题、描述、价格、促销、评价变化 | 规则发现六类事件；结构化发现、原文引文、推测与建议；真实 DeepSeek 已分析五类构造事件 | 已完成本轮联调；仍需独立标注、提示注入等语义评估及真实商品验证，不将引文匹配当作正确推理证明 |
| 输出可执行运营建议 | 三类任务、目标本店商品、证据、负责人和素材需求；已补计划、观察窗口、人工指标记录与无法评估原因 | 继续核实本店决策条件；成本和预算未接入，不具备条件时保留测算任务；经营效果尚无实测 |
| 频控、去重、异常识别与自动暂停 | 已有控制器及模拟网络测试，页面故障注入展示状态 | 用运行记录展示触发条件、请求数、下次允许时间和恢复方式；真实来源接入后再证明实际生效，不能将回放按钮当成真实控制器网络验证 |

## 优先级一：让AI分析有明确产物

本轮已将 `Analysis` 升为版本 2，分别展示：

- 事实证据：事件对应字段、变化前后值、快照或评价ID及原文片段。
- 语义识别：卖点、适用场景、服务承诺、促销机制、评价主题；明确来自哪个字段。
- 谨慎解释：对本店的可能影响，和仍需核实的条件。
- 建议：动作、负责人、执行条件、观察指标及评估计划；目标本店商品和优先级沿用规则任务，时间窗由人工记录。

金额和同规格可比性继续由程序计算。评价数量由程序聚合，模型只负责主题归类；同时展示样本数和分母，少量样本只支持核查任务。引用校验应包含片段与原文对应关系，不能仅检查事件ID存在。

已用自建构造文本完成真实模型联调，详见 [模型记录](model-validation.md)，保留首轮一次失败。后续已导入200条 [真实历史文案](history-data.md)，两条实际模型请求一条通过、一条回退。测试覆盖错误引用、错快照、长文本节选、合理无发现和数值越界；更完整的无语义变化、提示注入及独立人工语义评估仍待补，不能把模拟响应或规则草稿称为真实AI分析。

## 优先级二：建议形成可评估的运营动作

本轮已增加计划日期、观察窗口、实际动作、指标和单位、基线与后续值、数据来源及干扰因素，并保存反馈历史。没有指标数据时可说明“暂时无法评估”，不要求填写虚构增长。模型提供核实条件和评估计划，实际执行前仍需运营确认。

促销案例应回答三个问题：是否与竞品可比、本店是否允许调整、选择哪个有限动作试验。缺少成本或预算时不建议具体跟价。美工案例在现有交付和验收项上补充需要解决的本店信息缺口，以及后续观察哪类咨询或投诉。

业务规模、告警阈值和观察期限均应作为初始假设解释。例如价格阈值由运营配置，而不是每一个一分钱变化都生成同等优先的待办。原始变化仍保留；同商品同轮的标题、描述和评价可关联为一条待处理建议，保留各条证据。

## 优先级三：补足促销时间与数据范围

当前快照已有券额、门槛与价格确认标志，但没有结构化优惠有效期。下一轮需要记录开始/结束时间、时区、适用SKU、件数与人群；券到期即使文字与金额未变，也不能继续把旧券后价当成当前价格。新增优惠过期和条件不明确的案例，再根据获准来源响应完成映射。

评价时间窗、SKU映射和图文描述需要按来源分别声明。只有评价数量或评分时，不宣称完成评价正文主题分析；图文未取得时保持缺失。题目要求基础分析，无需为展示增加自动生成图片、自动改价或复杂多Agent架构。

## 优先级四：统一方案与实现的说法

主方案已注明为目标设计，但讲解还需逐项区分：

| 目标设计中的能力 | 当前实现状态 |
| --- | --- |
| 最多一次模型格式修复 | 当前格式或证据校验失败直接回退规则结果，没有独立格式修复回合 |
| 指数退避加抖动 | 当前有指数退避和Retry-After处理，没有随机抖动 |
| 按字段采用不同采集频率 | 当前按来源统一周期与商品轮转，没有独立字段调度 |
| 评价主题的时间窗数量与占比 | 当前提供新增评价样本与去重，没有主题聚合统计 |
| SKU、源记录ID、解析版本及完整原始响应追溯 | 当前只保存已实现的快照字段与内容哈希；上述统一结构尚未完整实现 |
| 多实例执行锁 | 当前为单进程锁，不能表述为分布式或跨进程幂等保障 |

上述项目按业务优先级实现或保留为后续设计即可，不需要为了凑完整把它们全部加入面试demo。

## 交付材料的取舍

题目明确以方案完整性与落地性为重点、无需提交代码。建议以精简方案为主，工程和录屏证明关键取舍：可比报价、未知信息、证据链、人工审核与异常暂停。将“62个构造案例通过”放在规则验证部分；来源、真实模型与经营效果分别列状态，避免一个总通过率掩盖不同验证层次。

面试前应能用自己的业务理解解释：为何选这些竞品、何时告警、为何不直接跟价、来源缺字段如何处理、模型出错如何发现，以及如何判断建议值得执行。提纲用于练习，提交时用自己的表达重新组织。
