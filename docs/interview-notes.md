# 面试口述与录屏提纲

用于自己理解和练习，不建议整篇照读或直接作为答卷提交。洗发水只是工程中的构造品类，讲解时应替换为自己熟悉且能解释的运营场景。

## 两分钟讲清方案

**解决什么问题。** 运营反复检查重点商品和竞品，容易漏掉优惠门槛、规格和内容变化。我希望系统每天给出一份带证据的待办：谁发生了什么变化、是否真的可比、运营该先核实什么。

**数据从哪里来。** 本店优先用获准的卖家接口；竞品另找允许该用途的来源。每个来源先验证权限、字段、频次、时效和留存条件。当前实际账号只有买家身份，已看到官方测试应用，但没有验证到商品查询权限；第三方也仍在核验，正式采集因此保持关闭。

**系统如何运转。** 定时任务按商品白名单轮转，限频与去重后获取快照。程序计算金额、优惠和前后差异；AI 负责识别文本里的卖点、评价需求并解释变化，可以在预算内再读一次证据。建议必须附事件与快照，最终由运营审核。

**建议怎样落地。** 同规格竞品到手价下降，先生成毛利与活动预算测算任务；描述新增使用场景，先核实本店是否有信息缺口，再形成带文案、画面和验收要求的美工需求。系统不直接改价或发布素材。

**异常怎么办。** 限流先退避，权限失效或返回登录页立即暂停；未知字段保持未知，历史数据过期后退出当前比价。先用构造集验证逻辑，再用真实获准数据验证采集与模型质量；业务收益需要后续观察或对照实验。

当前数据库已保留四件构造商品、六个事件、五类模型分析与人工反馈，直接查看即可。**默认不重置回放**：重置会清除回放分析和反馈。若使用全新数据库，可先依次推进四个场景建立数据；只有明确要重新跑场景且已另存需要留存的记录时才使用重置。

## 需要能回答的追问

**为什么是 Agent，而不是定时脚本？** 定时获取和金额计算本来就应该由程序负责。Agent 根据事件选择是否补读证据，再生成有条件的行动建议；工具、预算和执行权限由程序约束。已用真实 DeepSeek 分析五类构造事件，保存实际只读工具轨迹与引用；这证明有限流程可运行，尚不能证明真实市场分析质量。

**模型怎么发现降价？** 金额不用模型算。程序先对齐规格和购买条件，再计算到手价；模型解释其可能的运营意义。不同地区、件数或会员条件不直接比较。

**你说的评价分析是否覆盖全部用户？** 没有。只报告来源提供的新增样本。样本不足时创建核查任务，不能把一条评价说成普遍问题。当前实现有样本去重，真实来源专用分页和时间窗还需接入验证。

**字段丢了或后来恢复，算什么？** 已知变为未知是覆盖下降，不是降价、撤券或下架。恢复后先建立字段基线，下一次两个已知值再比较。独立的真实描述或促销变化仍可产生自己的事件。

**怎样证明建议有效？** 先看告警是否正确、证据是否充分、运营是否采纳和为何驳回，再按动作观察指标。促销看毛利与转化，详情说明看相关咨询和转化；同期活动会造成混杂，不能把变化全部归因于 Agent。

**62/62 说明已经可靠了吗？** 只能说明当前程序满足这份同一项目编写的构造案例，覆盖范围有限。要继续补充独立人工标注、真实数据、新品类及模型语义评估。报告保留最初 58 个案例的失败结果和升版原因，避免只展示最终高分。

**现在还缺什么？** 可用于该用途的真实商品来源、来源专用字段映射与 SKU/评价分页、至少三个真实调度周期。模型已接通，仍缺独立标注的语义评估和经营观察。促销有效期、主题聚合与告警合并也属于后续范围。GitHub 尚未上传，视频尚未录制。

## 展示前准备

1. 在仓库根目录执行 `uv sync --locked` 和 `uv run python run.py`。
2. 执行 `uv run pytest -q` 和 `uv run python -m evaluations.run --check --json artifacts/evaluation.json --markdown artifacts/evaluation.md`。
3. 先练一遍回放，把“观测竞品”和“建议操作的本店商品”分清；不用模型未实际生成的措辞。
4. 模型验证首轮有一次促销回退，最终受控重试通过；保留失败记录，不把五类冒烟检查讲成准确率。真实来源接通后按实际字段与运行记录重写录屏。
