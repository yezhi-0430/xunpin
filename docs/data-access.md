## 1. 已确认的资料与适用边界

| 官方资料 | 核对结果 | 对方案的影响 |
| --- | --- | --- |
| [应用软件开发商接入指南](https://developer.alibaba.com/docs/doc.htm?articleId=120867&docType=1&source=search&treeId=774) | 官方列出对应业务身份与应用接入路径 | 先核实自己适用的业务身份、申请条件和应用类型，不承诺个人一定可立即获批 |
| [自店在售商品接口](https://developer.alibaba.com/docs/api.htm?apiId=18) | `taobao.items.onsale.get` 需要授权，说明查询当前会话用户出售的商品 | 可以作为自店接入候选，不作为任意竞品查询接口 |
| [商品详情接口](https://developer.alibaba.com/docs/api.htm?apiId=24625&source=search) | `taobao.item.seller.get` 标记为需要授权 | AppKey 不等于拥有全部接口和数据权限；描述、规格及其他字段需实测 |
| [官方评价说明](https://developer.alibaba.com/docs/doc.htm?articleId=119661&docType=1&source=search&treeId=1) | 文档说明 `taobao.traderates.get` 仅支持卖家给出或得到的评价，并有时间与主评范围限制 | 不能用这条路径承诺取得任意竞品的全部评价；具体当前权限仍需核验 |
| [部分接口下线实施公告](https://developer.alibaba.com/support/announcementDetail.htm?id=25319&source=search) | 公告说明 `taobao.item.get` 等接口于 2018-01-22 下线 | 不把仍可搜索到的旧接口文档视为当前可用证明 |
| [部分 TAE 接口下线公告](https://developer.alibaba.com/support/announcementDetail.htm?id=25481&source=search) | 2019 年公告说明 `taobao.item.detail.get` 等接口下线及特定旧权限迁移安排 | 不推荐新项目接入已公告下线接口；历史迁移也不代表新申请者能获权限 |
| [淘宝客接口文档](https://developer.alibaba.com/docs/api.htm?apiId=64763) | 公开资料中有淘宝客商品查询能力；实际仍涉及应用与业务参数 | 仅列为待审查候选，不能由“不需要授权”推断无 AppKey、无用途限制或覆盖全部字段 |

以上是资料事实。方案据此作出的选择是：优先核对自店卖家授权路径，竞品另行取得明确适用的来源；这是设计判断，不是已取得授权的结论。

## 2. 当前可选择的三条路径

| 路径 | 优点 | 约束与选择标准 |
| --- | --- | --- |
| 官方授权能力 | 权限和接口规则可从平台核对 | 先看实际能申请的业务类型与接口；仅有自店能力不能覆盖全部竞品需求 |
| 已获相应许可的数据服务 | 有机会统一获得所需公开字段 | 必须核实上游取得方式、用途、商品范围、评价覆盖及留存条件；有接口不等于已获平台许可 |
| 平台明确允许的其他交付 | 若支持约定频率的报表或数据交付，可降低轮询 | 必须确认确有此能力和自动化使用许可；人工下载后导入不宣称为系统定时获取 |

建议采用前两条的组合设计；如果没有已批准的竞品来源，就保持竞品真实接入为未通过。不要为了演示改用未核实许可的网页抓取方式。

## 3. 对用户目前最实际的接入步骤

1. 确认是否有可配合的商家及店铺授权。没有商家主体时，不把卖家接口路线写成已具备。
2. 在 [淘宝开放平台](https://open.taobao.com/) 按实际身份查看入驻与应用类型，核对所需业务能否申请；如不能，明确记录原因，不选择与实际用途不一致的类型。
3. 对可申请的应用，核实商品、描述、促销和评价各自的接口权限、调用环境、授权条件与配额。只在本地安全位置配置凭证，不发送到聊天或提交 GitHub。
4. 并行核查竞品数据服务的资格与具体字段。尚未找到符合条件的服务前，不绑定服务商品牌或作价格、覆盖率承诺。
5. 完成下表验收，获得批准后才开启低频定时任务。真实数据不明显变化时仍可记录连续调度；变化检测另外用标注样例测试。

平台申请的审核时长、费用、可申请性和配额需要在实际控制台确认，本方案没有代为申请，也不承诺这些条件。

## 5. 接入不成功时的明确处理

- 申请不到权限：不发起请求，保留未配置状态，选择另一条可获准路径或如实说明依赖条件。
- 权限只覆盖部分字段：展示实际覆盖范围，关闭无数据依据的分析；完整需求验收不能标为全通过。
- 竞品评价无法取得：可以分析已获准的本店评价，竞品评价标为不可用；不自动改为抓取网页。
- 仅有本地样例：可以验证调度和分析逻辑，但 README、视频及方案都必须写明尚未完成真实获取验证。

对于本次“无需提交代码”的面试题，可以完整说明以上接入路径及实施条件；如果另做 GitHub showcase，只有获得真实调用记录后才能宣称采集能力已经落地。
