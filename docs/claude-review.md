# Claude新增数据审查与启动修复

日期：2026-10-21。用户要求保留原“巡品”界面，不增加模拟模式，直接使用Claude已生成的数据。

## 交付入口

- 原巡品工作台：http://127.0.0.1:8000/ 。根目录start.bat启动该界面。
- 原Claude输出目录的start.bat也转发到同一工作台，不再打开旧版白蓝界面。转发目标在其xunpin-target.json中；移动工作目录后需更新该文件。
- 保留原有“当前数据”与“流程回放”两个选择，没有新增模拟模式。历史真实文本仍从原侧栏进入。

## 数据核验

最初审查时Claude库有200商品、80分析、18告警、7策略；实际导入时源库已有220商品，其他三类数量仍为80/18/7。按当时现状只读导入，没有由本工作台额外生成商品或删去新增条目。

数据保存在独立state命名空间，只读展示默认概览、告警、建议、商品详情与已保存价格历史。正式接口仍未接通；正式监控表与已有回放不混入这些构造记录。价格只展示源文件标价，不推断到手价；不同品类不直接做竞品比价。原策略的置信度、销量与利润收益预测未作为有效结论展示。

## 审查发现与处理

| 问题 | 本轮处理 |
| --- | --- |
| Windows批处理UTF-8文字与纯LF触发命令碎裂，路径切换失败 | 启动批处理改为ASCII、CRLF，按脚本目录定位，中文目录和外部cwd实测 |
| 旧项目main/config/models的包导入混用 | 旧版本先修通以确认数据可用，后按用户纠正将旧入口转发原巡品，不以旧项目作为交付界面 |
| Python缺少异步SQLite/SQLAlchemy组件，依赖版本不适配3.13 | 旧环境独立补齐；巡品启动器优先使用本项目已有.venv，不依赖旧项目环境 |
| 启动器开出另一套界面 | 原、新入口均明确转向巡品8000；重复启动识别已有实例 |
| 单品分析忽略已加载商品，重新生成随机商品；价格与历史基线随机 | 新概览只读导入已保存数据，不调用旧随机分析链；有前后证据的流程仍使用原回放 |
| 策略包含硬编码85%置信度、销量提升15–20%等 | 不作为经营结论呈现，建议保留人工核实条件 |
| 旧商品列表只取100条，没有分页 | 原巡品中增加20条分页，可访问导入的全部商品 |
| 外部服务的health返回数组/null时端口提示崩溃 | 独立审查发现，2个回归先失败再修复，明确拒绝占用端口 |
