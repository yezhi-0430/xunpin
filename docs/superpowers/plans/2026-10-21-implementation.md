# 淘宝商品监控实施计划

> 执行方式：在本会话使用 executing-plans 逐项实现；按照 test-driven-development 验证重要业务行为。完整方案见 ../../solution-design.md。

**Goal:** 建成可以本地运行与展示的监控工作台，真实来源适配器可配置，缺少权限时明确禁用，流程回放与真实数据隔离。

**Architecture:** FastAPI 提供本地 API 和静态页面；SQLite 保存来源状态、快照、事件、任务及运行记录。独立调度器执行获准来源；确定性计算变化，模型通过有界核验工具解释事件并创建草稿。

**Tech Stack:** Python 3.11+、FastAPI、httpx、Pydantic 2、SQLite、无外部 CDN 的 HTML/CSS/JavaScript。

## 全局约束

- 真实请求仅来自本地配置的授权来源，官方卖家接口仅绑定自店。
- 没有凭证、范围与许可说明时不请求；不宣称完成真实接入验证。
- 回放单独标注，事件、快照与任务按模式隔离；不随机生成分析结论。
- 价格用整数分；缺失与过期信息不生成确定价格结论。
- 密钥不进入 API 响应、日志或 Git；限频、配额、去重与暂停不能由模型绕过。
- 自动发布、改价、购买服务与上传 GitHub 不属于此次本地实现。
